## Step 2 — Fix `staleTime` first

**Why first:** `staleTime` controls how long the cached data is considered _fresh_. While fresh, TanStack Query will not refetch on mount, focus, or reconnect. Biggest impact on perceived performance, so fix it first.

Change `staleTime: 0` → `staleTime: 60 * 1000`.

**Why `60 * 1000` and not `60000`:** the multiplication form documents the unit at the call site. Six months from now a junior teammate reads it and knows "60 seconds", not "60,000 of something".

**Why not zero:** `staleTime: 0` means every mount triggers a refetch — a refetch flood for data that almost certainly has not changed.

---

## Step 3 — Fix `gcTime` second

**Why second:** `gcTime` ("garbage-collection time") controls how long an _inactive_ query stays in the cache after the last component unsubscribes. It is independent of `staleTime`; it only matters when you navigate _away_ and come back. Fix it while you're still in the cache-policy mindset.

Change `gcTime: 5 * 60 * 1000` → `gcTime: 15 * 60 * 1000`.

**Why 15 minutes:** Books → Authors → Books should render instantly from cache and refetch in the background. 5 minutes is too short; 15 minutes gives a great cache-hit ratio.

---

## Step 4 — Fix `retry` third

The requirement is "at most 2 retries". The solution uses the predicate form:

Change `retry: 0` → `retry: (failureCount) => failureCount < 2`.

**Why the function form, not `retry: 2`:** later you may want "retry only on network errors". The predicate form composes — `(failureCount, error) => failureCount < 2 && error.status !== 404`. Starting with a function means that future change is one line, not a refactor.

---

## Step 5 — Confirm the `select` transform

```tsx
select: (books) =>
  books
    .filter((book) => (book.pageCount ?? 0) >= MIN_PAGES) // 1. keep ≥200 pages
    .sort((left, right) => (right.pageCount ?? 0) - (left.pageCount ?? 0)) // 2. desc
    .slice(0, 10), // 3. cap at 10
```

**Why the order matters:**

- _Filter before sort_ — sorting is O(n log n). Filtering first means we sort fewer items.
- _Sort before slice_ — slicing first would give you the first 10 of the _original_ order, not the top 10 by page count.

You should be able to explain that out loud before moving on. Nothing to change.

**Why `select` and not transform in the JSX:** `select` runs inside the query, so the cache stores the full server payload and only the derived output triggers re-renders. If `select` returns the same reference, React skips the re-render entirely.

## Common mistakes

- **Adding a hand-written `queryKey: ["books"]`.** `getApiV1BooksOptions()` already provides the key. Adding your own breaks the contract.
- **Moving the filter into the JSX.** `select` is the right place because it runs inside the query, not on every render.
- **Switching to `useQuery`.** The route wraps this in Suspense; `useSuspenseQuery` is the correct hook and gives non-nullable `data`.
